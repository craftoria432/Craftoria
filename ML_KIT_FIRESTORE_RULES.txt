Add these rules to your firestore.rules file to properly secure the 
seller_verifications collection:

─────────────────────────────────────────────────────────────────────────────────

// Seller Verifications Collection
match /seller_verifications/{userId} {
  // Users can only read/write their own verification
  allow read, write: if request.auth.uid == userId;
  
  // Admins can read all verifications
  allow read: if request.auth.token.admin == true;
  
  // Admins can update verification status
  allow update: if request.auth.token.admin == true &&
                   (request.resource.data.verificationStatus in 
                    ['approved', 'rejected', 'pending']);
  
  // Prevent deletion of verifications
  allow delete: if false;
}

─────────────────────────────────────────────────────────────────────────────────

EXPLANATION:

1. Users can read/write their own verification
   - Mobile app saves verification under their user ID
   - Users can view their own verification status

2. Admins can read all verifications
   - Web dashboard needs to see all verifications
   - Requires admin token in Firebase Auth

3. Admins can update verification status
   - Only allow specific status values
   - Prevents accidental data corruption

4. Prevent deletion
   - Verifications are permanent records
   - Audit trail is important

CUSTOM CLAIMS SETUP:

To set admin claims, use Firebase Admin SDK:

// Node.js example
const admin = require('firebase-admin');

admin.auth().setCustomUserClaims(uid, { admin: true })
  .then(() => {
    console.log('Custom claims set for user:', uid);
  });

Or use Firebase Console:
1. Go to Authentication → Users
2. Click on user
3. Custom claims (JSON):
   {
     "admin": true
   }

COMPLETE FIRESTORE RULES EXAMPLE:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Users collection
    match /users/{userId} {
      allow read: if request.auth.uid == userId || 
                     request.auth.token.admin == true;
      allow write: if request.auth.uid == userId;
    }
    
    // Seller Verifications collection
    match /seller_verifications/{userId} {
      allow read, write: if request.auth.uid == userId;
      allow read: if request.auth.token.admin == true;
      allow update: if request.auth.token.admin == true &&
                       (request.resource.data.verificationStatus in 
                        ['approved', 'rejected', 'pending']);
      allow delete: if false;
    }
    
    // Other collections...
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

─────────────────────────────────────────────────────────────────────────────────

TROUBLESHOOTING:

Issue: Mobile app can't save verification
→ Check: User is authenticated (request.auth.uid exists)
→ Check: Document path is seller_verifications/{userId}
→ Check: Rules allow write for authenticated users

Issue: Web dashboard can't read verifications
→ Check: Admin user has admin custom claim
→ Check: Rules allow read for admin users
→ Check: Admin is authenticated

Issue: Admin can't update verification status
→ Check: Admin has admin custom claim
→ Check: Status value is in allowed list
→ Check: Update operation is valid

─────────────────────────────────────────────────────────────────────────────────

SECURITY BEST PRACTICES:

✓ Users can only access their own data
✓ Admins have explicit admin claims
✓ Verification status is restricted to valid values
✓ Deletions are prevented
✓ All operations are logged by Firestore
✓ No public read access to verifications
